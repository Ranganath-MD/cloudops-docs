A Virtual Private Cloud (VPC) isolates your workloads in a private network you control.

![Typical VPC layout with public and private subnets](/images/networking/vpc-layout.svg)

## Layout

Typical production layout:

1. Public subnets for load balancers and bastion hosts
2. Private subnets for application and data tiers
3. Separate route tables per tier

<Callout title="CIDR planning" type="warn">
  Reserve enough address space for growth. Overlapping CIDRs block VPC peering and transit connectivity later.
</Callout>

## Security groups vs NACLs

<Tabs items={['Security Groups', 'NACLs']}>
  <Tab value="Security Groups">
    Stateful firewall at the instance/ENI level. Allow rules only; return traffic is automatic.
  </Tab>
  <Tab value="NACLs">
    Stateless subnet-level rules. Both inbound and outbound must be explicitly allowed.
  </Tab>
</Tabs>

## Example route table

```terraform title="terraform/vpc.tf"
resource "aws_route_table" "private" {
  vpc_id = aws_vpc.main.id

  route {
    cidr_block     = "0.0.0.0/0"
    nat_gateway_id = aws_nat_gateway.main.id
  }
}
```
