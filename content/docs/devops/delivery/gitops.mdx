---
title: GitOps
description: Keep cluster state synchronized with Git
---

GitOps stores desired state in Git and continuously reconciles the live environment.

## Benefits

- Auditable change history
- Faster recovery via `git revert`
- Consistent environments across clusters

<Callout title="Source of truth" type="info">
  Application manifests and environment overlays should live in Git. Avoid manual `kubectl apply` in production.
</Callout>

## Sync loop

```bash tab="Argo CD"
argocd app create api \
  --repo https://github.com/example/gitops.git \
  --path apps/api/overlays/prod \
  --dest-server https://kubernetes.default.svc \
  --dest-namespace api
```

```yaml tab="Flux"
apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata:
  name: api
  namespace: flux-system
spec:
  interval: 5m
  path: ./apps/api/overlays/prod
  prune: true
  sourceRef:
    kind: GitRepository
    name: gitops
```

<Tabs items={['Pull-based', 'Push-based']}>
  <Tab value="Pull-based">
    Controllers in-cluster pull from Git (Argo CD, Flux). Preferred for Kubernetes.
  </Tab>
  <Tab value="Push-based">
    CI pipelines push changes. Useful for non-Kubernetes targets, but harder to reconcile drift.
  </Tab>
</Tabs>
